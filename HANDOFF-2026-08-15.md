## What is left, and why the release is not cut

**Three groups. The first gates the third, which is the one with live user-visible harm.**

1. **`A6.1` — the invariant-3 instruments.** Not started, and it is the gate on everything
   below. Three of the four instruments CLAUDE.md invariant 3 tells you to re-measure with are
   compromised, and **the procedure is not executable as written**: two probes want a JSON shape
   nothing in `Tools/` produces any more. `score-line-separation` can move *opposite* to the
   property it names (87% → 87% across a change from no runaway line to a 2,139-character one).
   `probe-line-edges` is behaviourally identical to `score-corpus`'s own columns on 48 of 48
   documents, so the "four instruments" are three. `probe-text-offset`'s printed range is ~1.7%
   artifact. And **`score-corpus` prints `OK` for a document it measured nothing on**, which is
   the same false-green shape T12 just fixed twice elsewhere.

2. **The rest of `Tools/`** — `A12.2` (three tools isolate pages with PDFKit, changing the
   resolution production renders at, so **four `manifest.tsv` rows describe a pipeline nothing
   runs**), `A12.3` (`score-mrc` never applies R50's shrink, so its tone layers are 14–17x and
   `FEATURES.md`'s 4.96x figure is affected), `A12.4` (the corpus gate re-implements
   `pageIsAnImage` and admitted the two documents the app itself calls born-digital — D1's own
   subject), and the remainder of `A12.8`.

3. **The text layer and the crop box — `A1.2`, then `A1.1`, then `C23`.** In that order, because
   A1.1's only viable fix triples the sliver population A1.2 is about. Also open and small:
   `A1.3`, `A1.4`, `A2.4`, `A3.1` in its narrower form.

   **`C23` is the release blocker and the only open finding with harm a user sees today.** Every
   rebuild route publishes with no `/CropBox`, so the copy displays what the original hid — **14
   of 233 corpus documents, 577 of 16,987 pages, worst case 34.7% of the sheet**. Its fix is a
   geometry change on the default route: carry `/CropBox` through `Flattener.flatten`'s
   `beginPDFPage` *and* into `JBIG2.assemble`'s page dictionary, in the rebuilt page's own
   coordinate space — the source crop rect through the same transform
   `SearchableWriter.cropRegion` uses, because the rebuild bakes `/Rotate` in and swaps the box.
   C13's entry records that the obvious check does not work: re-OCRing the published copy can
   only ever report what is *displayed*, so the test has to lift the trim off a throwaway
   duplicate first.

**Why the release is not cut.** C23 changes what a published page displays on 6% of the corpus,
and the instruments that would say whether the change is right are the ones in group 1. Cutting
1.13.0 now would ship twenty-three fixes and leave C23 live for another release; cutting it after
an unmeasured C23 would be worse. **That is the owner's call, not mine** — everything listed
above is on `main`, nothing is half-applied, and neither choice is blocked by anything except the
decision. If the answer is "ship what is done", the release needs only the version bump, the
CHANGELOG, `./build.sh`, the DMG, a tag and `gh release`, with the corpus gate re-run first
(it reads pixels now, T9) and the annotation feature left off by default and unadvertised.

## Things this session got wrong, so you can calibrate

Every one of these was caught by the project's own controls rather than by care.

- **`.rounded()` in R61's `sauvolaWindow`** would have moved the shipped Sauvola window by a
  pixel on about half of all pages — a threshold change on the default route, inside a fix for a
  trap. Caught by reviewing the staged diff before committing it.
- **A13.1's abort is placement-dependent.** A NUL raises only when something follows it; in the
  final position it silently *truncates* the value instead. The review recorded only the abort. A
  four-case probe against the real `Process.arguments` found the rest.
- **R73's first register text claimed the suite aborts *instead of* failing a check.** Its own
  mutant's saved output shows one FAIL line and *then* `exit=134`. Reading `mutation-out/`
  replaced the sentence.
- **The skip-census figures were hand-counted wrong** (16 and 13; measured 14 and 12), and the
  self-verifying assertion added in the same commit caught it before it landed. Static counting of
  `check(` lines over-counts, because some sit in branches that do not all execute.
- **A3.3's existing check asserted the opposite of the truth** — it was R26's belief written
  down. Verified A3.3's claim against `Recogniser.render` before inverting the check.
- **My own A5.3 door checks passed for the wrong reason** when they shared a model: `start()` got
  through, set `isRunning`, and `clearFiles` then refused on the guard it already had.
- **The A9.3 leak fixture has been manufacturing a stranded process on every run** and calling it
  a pass, because it asserted only `took < 5`.
- **`pgrep -f 'build/tests'` matches the waiter loops that contain the string**, including
  themselves. Four of them once waited on each other while nothing ran. Now in CLAUDE.md.

The pattern is the one CONTRIBUTING §3 already names, and it did not stop being true because
somebody was watching for it: **the instrument is wrong more often than the code, and most
convincing when it agrees with you.**
