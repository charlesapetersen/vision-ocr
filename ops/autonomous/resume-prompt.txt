STEP 3 — DO IT. The non-negotiables, from CLAUDE.md and CONTRIBUTING.md:
  * **Your own worktree, on an `auto/` branch.** Never work in the primary checkout — the owner has live
    interactive sessions there, and one of them may be mid-commit.
        stamp="$(date +%Y%m%d-%H%M%S)-$$"
        git worktree add "/private/tmp/vo-$stamp" -b "auto/$stamp" && cd "/private/tmp/vo-$stamp"
    The `auto/` prefix is load-bearing: the daemon's housekeeping GCs `auto/*` worktrees once they are
    provably pushed AND clean, and touches nothing else. The owner's own `work/*` worktrees are never
    reclaimed. Confirm you are in your own worktree before editing anything.
  * **⛔ NEVER RUN TWO TEST SUITES AT ONCE — in any two worktrees.** `build/tests` has no bundle identifier,
    so `UserDefaults.standard` lands in `~/Library/Preferences/tests.plist` keyed by the process name, and
    every worktree shares that ONE file. A second suite's `resetPrefs()` wipes the first one's settings
    mid-run: measured 882/883 → 877/879, with failures unrelated to any change. That is the worst kind of
    result — evidence that is WRONG rather than absent. So always:
        ops/autonomous/test-lock.sh run --label session -- ./run_tests.sh
    This includes suites started by any subagent you launch. To check who holds it:
    `ops/autonomous/test-lock.sh status`. If it says a suite is running, WAIT — that is correct behaviour,
    not a fault. And when you need to know whether a suite is live, it is `pgrep -x tests`, never
    `pgrep -f build/tests`: the `-f` form matches every waiter including your own shell, and four such loops
    once sat waiting on each other while nothing ran.
  * **A failing test FIRST, and watch it fail.** CONTRIBUTING records three tests that passed against a
    deliberately reintroduced bug. A fix without a test that fails without it is not finished. Tests are
    `check(...)` calls in `Tests/main.swift`.
  * **A sibling sweep**, and the answer goes in the commit message: grep for who else does this thing. Half
    this register's entries are one instance of a pattern that had several.
  * **A mutant** in `Tools/mutate.py` if you changed a constant or a guard, run scoped
    (`python3 Tools/mutate.py --only <substring>` — never the ~70-minute full catalogue), with the row
    appended to `Tools/mutation-log.tsv`. A **`Tools/fault-inject.sh` case** if you added an error branch.
    ⚠️ Do not edit `Sources/` while `mutate.py` is running.
  * **Never write a real corpus.** `testdocs/` is 1.2 GB of third-party copyrighted PDFs that is not
    committed and cannot be regenerated without the owner's Zotero library. Read it; never write it. Test
    output goes to `mktemp` scratch. File safety beats getting it done.
  * **NEVER `git commit --no-verify`** (it is denied at the tool layer too). The pre-commit hook running the
    suite is the only thing between this run and pushing untested code. If the suite fails, fix it or stop.
  * **Never `--force` past a git or tool refusal** (`worktree remove`, `reset --hard`, `clean`, `branch -D`).
    A refusal means STOP and investigate: dirty files may be a parallel session's work.
  * The five **invariants** in CLAUDE.md §Invariants have each destroyed user content before. If you touch
    `SearchableWriter`, re-measure ALL FOUR text-layer properties — each has been broken by a fix to another.
  * Environment traps that have each cost real time: a **backgrounded shell has essentially no PATH** (use
    absolute paths; `basename`/`cut`/`timeout` fail silently); a **redirected suite log lags up to 4 KB**, so
    `tail -f` looks stalled on a healthy run — watch the process, not the log; **`nohup … &` reports success
    immediately** while the work runs orphaned; the volume is **case-insensitive**; corpus filenames contain
    spaces and **U+00A0** — glob, never retype.

STEP 3.5 — GUI VERIFICATION, OFF the owner's screen:
  For a change with a visible effect, `Tools/vm-gui-check.sh [windows|reopen|settings|all]` runs the checks
  that only a running app can answer, inside the Tart VM with its own virtual display. It exits 0 pass /
  1 fail / 3 could-not-run, and a `3` is a SKIP — record it and move on, do not treat it as a pass.
  ⛔ Nothing you run may draw on the owner's physical display. `open`, `osascript`, `cliclick`,
  `./build.sh --install` and `./build.sh --run` are denied at the tool layer. Do not engineer around that:
  take the VM route, or leave the check for the owner with a note. Also never rebuild while the owner may be
  running `VisionOCR.app` — macOS SIGKILLs a running app whose signature changed underneath it.

VERIFICATION DISCIPLINE — this project's culture, and it is stricter than most:
  * **State plainly whether a finding was verified by running code or only reasoned about.** Never report a
    change as working without the suite passing. "An entry without evidence is a rumour."
  * **When a measurement is surprising, suspect the instrument first.** Several "confirmed" findings here
    were artifacts: `difflib` autojunk on repetitive text, a glob matching unrelated files, ImageMagick's
    `AE` exceeding the pixel count, a probe counting short lines as failures. Ten checks in this register's
    history *could not fail* — they were written, looked green, and asserted nothing.
  * Prefer `Edit` over scripted text-slicing on source files: an over-broad Python slice once deleted four
    functions from `Model.swift`.
  * Do not invent numbers. If you did not measure it, say so.
